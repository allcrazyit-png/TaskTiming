# 手動輸入工作位置重新設計

**日期**：2026-06-23  
**主題**：將手動輸入產品功能從篩選器區域移至首頁「我的最愛」旁邊  
**目標受眾**：工廠作業員（40歲以上）  

---

## 概述

目前手動輸入工作（用於記錄清單外的臨時任務，如掃廁所）藏在「找其他產品」展開式篩選器內，需要多步驟才能找到。根據使用數據（週 3-4 次）及員工反饋，這個功能應該更容易發現，但不應該搶走常用產品（我的最愛）的視覺焦點。

**設計方案**：將手動輸入按鈕移至首頁「我的最愛」卡片列表下方右側，保持簡潔的視覺層級。

---

## 需求與約束

### 使用場景
- **頻率**：週 3-4 次（低頻）
- **性質**：臨時、非預期的任務（如臨時分配的非產品工作）
- **期望**：員工進首頁應該立即看到有這個選項，無需層層點開

### 設計原則（來自 CLAUDE.md）
- 常用產品（我的最愛）應放在首頁最顯眼的位置
- 流程步驟越少越好，避免多層下拉選單
- 按鈕觸控目標最小 64px 高
- 字型預設使用大字（text-large 模式）

### 可見性條件
- **當沒有我的最愛時**：不顯示手動輸入區域（保持首頁整潔，引導員工先建立最愛）
- **當有我的最愛時**：同時顯示我的最愛卡片 + 手動輸入按鈕

---

## UI 設計

### 布局結構

```
首頁
├─ 常用產品區域
│  ├─ 當無最愛時：
│  │  └─ 灰色提示「尚未有常用產品」（隱藏手動輸入）
│  └─ 當有最愛時：
│     ├─ 標題「♡ 我的最愛」
│     ├─ 我的最愛卡片列表（垂直堆疊）
│     └─ 下方右側：「+ 手動輸入工作」按鈕
├─ [找其他產品] 按鈕（展開/收起篩選器）
└─ 篩選器與產品列表（展開時顯示）
```

### 手動輸入按鈕設計

| 屬性 | 說明 |
|------|------|
| **位置** | 我的最愛卡片列表下方，靠右對齐（margin-right 與卡片對齐） |
| **形式** | 簡潔按鈕或輕量卡片 |
| **尺寸** | 約 120-150px 寬；高度至少 48px（考慮觸控目標） |
| **文字** | `+ 手動輸入工作`（或簡化為 `+ 輸入工作`） |
| **圖示** | Material Symbols 的 `edit` 或 `add` |
| **顏色** | 淡灰或灰藍背景（#E2E8F0 或類似），區別於常規產品卡片的白色背景 |
| **邊框** | 2px 虛線邊框（表示「補充」而非主要入口） |
| **互動** | 點擊時打開簡單 modal |

**視覺等級**：
- 我的最愛卡片：視覺主體（白色背景、陰影、彩色按鈕）
- 手動輸入按鈕：次級、補充性（淡色背景、虛線邊框）

## 交互流程

### 1. 點擊手動輸入按鈕
員工在首頁看到「+ 手動輸入工作」，點擊。

### 2. 彈出簡單表單 Modal

```
標題：手動輸入工作

輸入框：
  Label: 工作內容 *（必填）
  Placeholder: 例如：掃廁所、整理材料、清潔設備
  
[取消] [開始工作]
```

**表單設計細節**：
- 輸入框高度 ≥ 48px，字型大（text-large）
- 只需輸入「工作內容名稱」，無需品番
- 驗證：名稱不得為空或純空白
- 錯誤提示：「請輸入工作內容」

### 3. 進入 Input 頁面

點擊「開始工作」後，導航至 `/input`，傳遞以下 state：

```javascript
{
  productName: "掃廁所",      // 用戶輸入的工作內容
  partNumber: "",              // 空值
  carModel: "未指定",          // 預設值
  standardTime: 0,             // 預設 0
  operator: selectedOperator,  // 當前登入員工
  productImage: null,          // 無圖片
  category: null               // 無類別
}
```

**Input 頁面行為**：
- 正常流程不變（輸入時間、良品數、報廢數）
- 無類別標籤顯示，或顯示灰色「其他」標籤
- 確認送出後，記錄至 Google Sheets 的「紀錄」表

## 代碼變更概述

### Home.jsx 修改

1. **移除篩選器中的手動輸入區域**
   - 刪除 `isCustomProduct` 狀態在篩選器中的展開式區域
   - 簡化篩選器，只保留：車型 → 品番 → 產品列表

2. **新增首頁手動輸入按鈕**
   - 在 `favoriteProducts.length > 0` 的條件下，於我的最愛卡片列表後添加手動輸入按鈕
   - 按鈕點擊時打開 modal

3. **簡化自定義產品表單**
   - 保留 `customProductName`、`showCustomModal` 等狀態
   - 移除 `customPartNumber`、`customPartNumberInput`（簡化為只輸入名稱）
   - 簡化 `handleStartCustomWork` 邏輯：
     ```javascript
     {
       productName: customProductName.trim(),
       partNumber: "",
       carModel: "未指定",
       standardTime: 0,
       operator: selectedOperator,
       productImage: null,
       category: null
     }
     ```

4. **Modal 設計**
   - 使用現有的 modal 樣式（參考密碼 modal 或歷史 modal）
   - 簡潔的輸入框 + 兩個按鈕（取消 / 開始工作）

## 視覺與可達性

### 色彩與對比
- 手動輸入按鈕背景：淡灰色（accessibility contrast ratio ≥ 4.5:1）
- 文字：slate-700 dark:slate-300
- 邊框：slate-300 dark:slate-600

### 觸控目標
- 按鈕高度 ≥ 48px（符合 WCAG 建議的 44px）
- 按鈕寬度 ≥ 120px
- 按鈕周圍有足夠的空白區域，防止誤點

### 字型與語言
- 使用 text-large 模式（符合 UI 設計原則）
- 支援多語言：中文、越南語、印尼語（通過 i18n）

## 在沒有最愛時的行為

當 `favoriteProducts.length === 0` 時：
- 顯示「尚未有常用產品」的灰色提示框（保持現狀）
- **不顯示**手動輸入按鈕
- 員工可通過「找其他產品」篩選和開始工作，或等待建立最愛後使用手動輸入

**理由**：
- 保持首頁簡潔，不會因為沒有最愛就多出一個孤立的按鈕
- 邏輯上，既然還沒有常用產品，臨時工作功能也可以隐藏
- 一旦有最愛，兩者同時出現，形成「常用」和「臨時」的清晰對比

## 測試場景

| 場景 | 預期行為 |
|------|--------|
| 員工剛登入，無最愛 | 首頁顯示「尚未有常用產品」，無手動輸入按鈕 |
| 員工有 1 個最愛 | 顯示 1 張卡片 + 手動輸入按鈕 |
| 員工有多個最愛 | 卡片垂直堆疊，最後一張下方右側顯示手動輸入按鈕 |
| 點擊手動輸入 | Modal 彈出，焦點在輸入框 |
| 輸入空值後點確定 | 顯示錯誤「請輸入工作內容」 |
| 輸入「掃廁所」並確定 | 導航至 Input 頁面，productName = "掃廁所" |
| 在 Input 頁面完成並上傳 | 記錄至 Google Sheets |
