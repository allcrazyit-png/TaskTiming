# 公共區域看板螢幕（飲水機旁）設計

日期：2026-11-21

## 目的與原因

在公司公共區域（飲水機旁）放一台螢幕，持續播放看板內容。員工經過時看一眼，就能注意到兩件事：

1. **今天的公告**（公告不一定每天都有）
2. **今日產量**

現有的「今日看板」頁面（`/battle`，`src/pages/BattleReport.jsx`）是為手機設計的，直接拿來投在螢幕上不可行：

- 讀資料要員工登入（Supabase access token + refresh token），公共螢幕掛某人的帳號遲早會被登出，而且會弄亂那位員工的公告已讀狀態。
- 版面是直式、要捲動，部分文字只有 10–11px，遠看讀不到。
- 資料只在進入頁面時抓一次，不會自動更新。

## 目標

- 新增一個螢幕專用頁面，用一個網址打開就能長時間無人看管地運作，不需要任何人登入。
- 遠看讀得到：橫式全螢幕、大字。
- 公告同時顯示中文、越南文、印尼文。
- 資料自動更新，斷網恢復後會自己接上。

## 非目標

- 不改動現有手機版 `/battle` 頁面的行為。
- 不在螢幕上顯示個人資料、個人排名或個別紀錄（作業員姓名只出現在值日生欄位，與手機版相同）。
- 不做公告的已讀/未讀。
- 不處理硬體採購。
- 不支援智慧電視內建瀏覽器等舊瀏覽器（不加 legacy build）。

## 執行裝置

使用者決定：**一台迷你電腦接到螢幕上，用 Chrome 開啟**。因此現有的 Vite 建置設定可直接使用，Screen Wake Lock API 在 Chrome 上可用。

## 反目標（做出來但等於失敗）

- 螢幕某天卡在登入頁或錯誤頁，沒有人知道怎麼修。
- 沒有公告時出現空白區塊或「目前沒有公告」，看起來像壞掉。
- 螢幕網址能拿來寫入資料或讀到個人資料。

## 限制

- 前端：React + Vite + Tailwind，HashRouter，部署在 GitHub Pages（`/TaskTiming/`）。
- 後端：Supabase。產量來自 `public.task_timing_records`；公告來自 `public.task_timing_notice_snapshot`（`source_sheet_id = '1xo4YhDuxh-wpstg7tmAqW4orB9aBheF1CUFzM1TDWKw'`）。兩者目前都只允許 `authenticated` 讀取。
- 線上資料庫的變更（新增函式、資料表）必須先經使用者同意才能套用。
- 不得 `git push` 或 `npm run deploy`，除非使用者明確說要。

## 考慮過的做法

| 做法 | 內容 | 取捨 |
|---|---|---|
| A. 專用看板員工帳號 | 螢幕登入一個「看板」帳號，靠 refresh token 續期 | 後端不用改；但斷網太久或帳號在別處登入就會被登出，要有人拿鍵盤重新登入；帳號有一般員工的寫入權限 |
| **B. 唯讀看板函式 + 網址密鑰（採用）** | 後端新增一個不需登入的函式，用網址中的密鑰驗證，只回傳彙總產量與有效公告 | 永遠不用登入、可自動恢復；要新增一個資料庫函式；網址外流時可透過換密鑰讓舊網址失效 |
| C. 完全公開，不設密鑰 | 同 B 但無驗證 | 最簡單；但任何知道網址的人都能看到內部公告與產量 |

使用者選 **B**。理由：公共螢幕最怕「哪天卡在登入頁、沒人會修」，B 從根本上避開這個問題。

## 設計

### 後端（Supabase）

新增 migration `supabase/migrations/20261121_public_board.sql`：

1. **密鑰資料表** `public.task_timing_board_keys`
   - 欄位：`key_hash text primary key`（密鑰的 SHA-256 十六進位）、`label text`、`created_at timestamptz default now()`。
   - 開啟 RLS，`anon` 和 `authenticated` 都沒有任何權限。只存雜湊值，不存密鑰原文。
   - 換密鑰 = 刪除舊列、插入新列。
2. **函式** `public.task_timing_public_board(p_key text)` 回傳 `jsonb`
   - `security definer`，`set search_path = public`。
   - 先比對 `encode(sha256(p_key::bytea), 'hex')` 是否存在於 `task_timing_board_keys`；不符合時拋出錯誤（不回傳任何資料）。
   - 以台北時間的今天（`(now() at time zone 'Asia/Taipei')::date`）計算，**只**回傳：
     - `todayGoodCount`：今日良品數總和
     - `todayOperators`：今日上線人數（不重複的作業員數）
     - `avgEfficiency`：今日平均效率，公式與 `task_timing_battle_report` 相同
     - `todayRecordCount`：今日上傳筆數
     - `cumulativeTotal`：累計良品數總和
     - `todayDefects`：`{ missing, deform, appearance, other }` 今日各類不良總數
     - `notices`：`task_timing_notice_snapshot` 中上述 source 的 `notices` 陣列，伺服器端只保留今天有效的公告（規則同前端 `getActiveTaskTimingNotices`：`content` 非空、`start_date <= 今天`、`end_date` 為空或 `>= 今天`），且每則只回傳 `content`、`content_vi`、`content_id`
     - `today`：伺服器判定的日期字串
   - 不回傳作業員姓名、編號、品番或任何個別紀錄。
   - `revoke all ... from public`，`grant execute ... to anon, authenticated`。
3. 密鑰產生：由建置者產生一組隨機長字串（至少 32 字元），把雜湊值寫入資料表；密鑰原文**只交給使用者**，不寫進 repo、不寫進 commit。

### 前端

1. **新路由** `/tv`（`src/App.jsx`），對應新頁面 `src/pages/TvBoard.jsx`。
   - 網址：`https://allcrazyit-png.github.io/TaskTiming/#/tv?key=<密鑰>`。
   - 不顯示底部導覽列、不讀 `savedOperatorId`、不需要登入。
2. **資料服務**：在 `src/services/taskTimingRecords.js` 新增 `fetchPublicBoard({ key, signal })`，用 `SUPABASE_PUBLISHABLE_KEY` 以 anon 身分呼叫 `/rest/v1/rpc/task_timing_public_board`。
3. **更新與容錯**
   - 每 1 分鐘自動重新抓取（使用者決定）。不使用 Supabase Realtime：避免在紀錄表加觸發器影響上傳流程，也不需新增套件；1 分鐘延遲對路過看一眼的螢幕已足夠。用量約每月 130 MB 傳輸、每天 1,440 次呼叫，遠低於免費方案額度。
   - 抓取失敗時**保留上一次成功的畫面**，只把角落的「更新於 HH:MM」變成警示色，下次排程繼續重試。
   - 只有在伺服器明確回報密鑰錯誤（或網址缺少密鑰）時，才顯示大字的設定錯誤訊息（例如「看板網址的密鑰不正確，請洽管理人員」）。如果是網路錯誤（例如凌晨重新載入時剛好斷網），就顯示「連線中…」並持續重試，不顯示密鑰錯誤。（建置者的判斷）
   - 日期跨過午夜時，下一次更新自然會拿到新的一天。
   - 每天凌晨（例如 04:00）整頁重新載入一次，以取得新版程式並釋放記憶體。
4. **版面與風格**：以使用者確認過的樣品 `tv-board-preview.html`（Tesla 黑版本）為準。內容涵蓋手機版今日看板的全部項目。
   - **風格（使用者選定：Tesla 黑）**：純黑背景、白字，只有一個強調色（紅 `#e82127`），只用在「公告」標題、不良合計、斷線狀態。沒有卡片、外框、漸層或表情符號；區塊之間只用細線分隔。大數字使用細字重（200–300）、等寬數字。不跟隨 `appTheme`。
   - 畫面固定 16:9 比例，以 container query 單位（`cqh`/`cqw`）隨螢幕縮放。

```
組裝課 今日看板          11 月 21 日 星期六 14:37          ● 即時 · 更新於 14:37
─────────────────────────────────────────────────────────────────────────────
公告                    1 / 2 │ 今日產量
組裝前請確認卡扣完整。          │ 1,240 件            （超大細字）
發現缺料請先隔離，並通知領班。   │ ──────────────────────────────
TIẾNG VIỆT …                  │ 5 人 上線 │ 102% 平均效率 │ 8 筆 上傳
BAHASA INDONESIA …            │ 累計產量 488,221    距離 500K 還差 11,779 件
━━━━━━  ──────                │ ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
─────────────────────────────────────────────────────────────────────────────
今日不良  23 合計 │ 6 缺料  3 變形  12 外觀  2 其他    本週值日生  杜氏美蓮 #15 │ 志丹 #84
```

   - **最上方資訊列**：左「組裝課 今日看板」，中間日期、星期、時鐘，右邊綠點＋「即時 · 更新於 HH:MM」；抓取失敗時改為紅色「連線中斷 · HH:MM 的資料」。
   - **有公告**：上半部左右兩欄。左欄公告：中文最大字，越南文、印尼文接在下方、字級較小、灰色；某語言欄位為空時不顯示該段。多則時每 15 秒輪播，右上角顯示「1 / 2」，底部每則一條細進度線。單則內容超出高度時，停 3 秒後緩慢向上捲動，捲完停留再換下一則。右欄：今日產量、上線／平均效率／上傳三格、累計產量與里程碑（10K、50K、100K、500K、1M）進度線。
   - **沒公告**：上半部只有產量欄，產量數字更大。不顯示任何「沒有公告」字樣。
   - **最下方一條**：今日不良（合計、缺料、變形、外觀、其他）與本週值日生（女生、男生各一位，附員工編號與下週人選；資料由前端 `src/utils/dutyRoster.js` 計算，不經後端）。
   - 標籤文字以中文為主，旁邊或下方附越南文、印尼文小字；文字放在 `src/i18n.js` 現有的三語結構中。
5. **防止螢幕休眠**：頁面在支援的瀏覽器上使用 Screen Wake Lock API；不支援時忽略。

### 安裝說明（交付給使用者）

交付時附一段簡短的迷你電腦設定說明：
- 用 Chrome 的 kiosk 模式（`--kiosk <網址>`）開啟上述網址，並設為開機自動啟動，這樣停電復電後會自己回到看板。
- 關閉作業系統的螢幕休眠和自動睡眠。
- 關閉 Chrome 的「還原頁面」提示，避免異常關機後畫面被提示框擋住。
- 換密鑰的方法。

## 由建置者決定的部分

- 輪播秒數、自動捲動速度、確切字級與顏色（以上數字為起點）。
- `TvBoard.jsx` 的元件拆分方式。
- 函式錯誤時拋出的錯誤碼／訊息格式。
- 是否寫自動化測試，以及測試範圍（至少驗證：密鑰錯誤時不回傳資料；有/無公告兩種版面；抓取失敗時保留舊資料）。
