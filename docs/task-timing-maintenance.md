# TaskTiming 維護手冊

最後更新：2026-10-02

## 資料分工

| 資料 | 維護來源 | 網站使用來源 |
| --- | --- | --- |
| 產品主檔 | Google Sheet「產品總表」 | Supabase `task_timing_products` |
| 員工姓名與編號 | Google Sheet「員工資料」 | Supabase `task_timing_employees` |
| 員工密碼 | Google Sheet「員工資料」的「密碼」欄 | Supabase Auth |
| 組裝作業紀錄 | 網站經 Google Apps Script 寫入 Google Sheet「組裝紀錄」 | Supabase `task_timing_records`（戰報查詢鏡像） |

Sheet 是產品、員工與組裝紀錄的人工維護主檔；Supabase 是網站快速讀取的鏡像與登入服務。組裝上傳永遠先寫入 Sheet，寫入成功後才鏡像到 Supabase；Supabase 暫時失敗不會讓已寫入 Sheet 的生產紀錄遺失。

產品鏡像規則：Supabase 只鏡像**非射出**的產品，並以「品番＋類別」這組配對當作一筆資料的身分。同一個品番出現在不同工序（例如「組裝」「包裝」「檢查」）是刻意保留的，每個工序各自是一筆；Sheet 刪掉某個品番＋類別的組合，下次同步就會從 Supabase 刪除該筆。

組裝紀錄鏡像規則：每一筆以 `Supabase紀錄ID` 作為固定身分，`Supabase同步狀態` 顯示「已同步」或錯誤內容。既有資料會以每批 1,000 筆補同步；未完成時建立下一個一分鐘單次觸發器，另有每 10 分鐘的定時補漏同步。定時補漏只新增或更新；在 Sheet 刪除整列時，刪除列觸發器會立即完整比對並自動從 Supabase 刪除缺少的紀錄，不需要手動按同步。

## 日常操作

### 修改或新增員工

1. 在 Google Sheet「員工資料」修改員工編號、姓名或密碼。
2. 新增員工與要變更密碼的員工，密碼必須至少 6 碼。
3. 從試算表選單執行「同步員工資料到 Supabase」。
4. 確認同步結果沒有失敗員工編號。
5. 用一位安全的測試員工在網站確認新密碼可登入，舊密碼不可登入。

同步程式會記錄密碼的不可逆比對值；重複執行同步時，不會重設密碼未變動的員工，也不會中斷他們的登入。第一次啟用這版同步程式時，既有員工密碼只建立比對基準，不會重設；若正好要在第一次執行時更改密碼，先同步一次建立基準，再修改密碼並再次同步。

### 刪除員工

1. 在 Google Sheet「員工資料」直接刪除該員工整列。
2. 系統自動完整比對員工名單，並刪除 Supabase 員工名單與 Auth 登入帳號；不需要再按手動同步，也不會刪除過去的生產紀錄。
3. 如果誤刪，在 Sheet 加回同一員工編號、姓名與至少 6 碼的密碼，再執行一次「同步員工資料到 Supabase」以重建帳號。

刪除員工觸發的自動同步不會重設其他員工的密碼。

### 修改產品

1. 在 Google Sheet「產品總表」修改產品資料。
2. 從試算表選單執行產品同步。
3. 確認同步完成的訊息：已同步筆數、略過的射出與重複筆數、刪除的舊產品筆數。
4. 確認同步完成後重新整理網站，產品清單會由 Supabase 讀取。

## 網站何時使用 Google Sheet

| 功能 | 是否讀寫 Sheet | 說明 |
| --- | --- | --- |
| 首頁 | 否 | 產品、員工讀 Supabase；最近上傳時間讀本機瀏覽器資料。 |
| 員工登入 | 否 | 由 Supabase Auth 驗證密碼。 |
| 上傳作業 | 寫入 | 經 Google Apps Script 先寫入組裝紀錄，再鏡像到 Supabase。 |
| 戰報 | 否 | 登入後呼叫 Supabase RPC，讀取伺服器端彙總結果。 |
| 員工同步 | 讀取 | 新增或修改時可手動同步；刪除整列時會自動刪除 Supabase 員工與 Auth 帳號。 |
| 產品同步 | 讀取 | 手動執行時讀「產品總表」並寫入 Supabase。 |

### 組裝紀錄同步

- Sheet 的 W 欄為 `Supabase紀錄ID`，X 欄為 `Supabase同步狀態`。
- 新上傳會先完成 Sheet 寫入，再嘗試寫入 Supabase。
- 若狀態不是「已同步」，定時觸發器會重新補同步，不必要求作業員重複上傳。
- 要刪除錯誤紀錄時，在 Sheet 使用「刪除整列」；系統偵測到刪除列後會自動完整同步，不需要再操作選單。
- 自動完整同步會先處理新增與待重試紀錄；只要還有失敗或待處理資料，本次就不執行刪除。
- 只有選單中的「立即完整同步生產紀錄」會保留刪除筆數確認畫面；刪除整列觸發的自動同步不再要求按「是」。
- 誤刪後可將原資料重新加回 Sheet；下次完整同步會產生新的 `Supabase紀錄ID` 並建立新紀錄。
- 戰報只允許已登入的員工透過 `task_timing_battle_report` RPC 取得彙總資料；匿名使用者不能直接讀取整張紀錄表。

### 首頁最近上傳提示

首頁的「最近上傳」只使用該手機瀏覽器保存的最近 30 筆上傳紀錄。

- 顯示「最近上傳：今天 HH:mm」或日期與時間。
- 換手機、清除瀏覽器資料，或從另一台裝置上傳時，這個提示不會反映舊紀錄。
- 這是刻意的效能設計：首頁不會為此讀取組裝紀錄 Sheet。

## 安全規則

- 員工密碼不得放入 Supabase 公開資料表、前端程式或 localStorage。
- 網站只把登入時輸入的密碼交給 Supabase Auth 驗證。
- `task_timing_employees` 只提供員工編號與姓名給網站讀取。
- 不要在 Git、Sheet 註解、螢幕截圖或聊天訊息記錄 Supabase service role key。

## 發布與部署

| 類型 | 必要動作 |
| --- | --- |
| React 網站程式修改 | 執行 `npm run deploy`，發布至 GitHub Pages。 |
| Apps Script 同步程式修改 | 手動貼入 Google Apps Script、儲存，並依 Web App 設定重新部署。 |
| Sheet 資料修改 | 執行對應的員工或產品同步選單。 |

GitHub Pages 部署不會更新 Apps Script；Apps Script 儲存或部署也不會更新網站。這兩件事必須分開完成。

## 異常排查

| 現象 | 優先檢查 |
| --- | --- |
| Sheet 改了員工／產品，網站沒變 | 是否已執行對應 Supabase 同步。 |
| 員工無法登入 | 密碼是否至少 6 碼、同步是否成功、是否輸入正確員工編號的密碼。 |
| 幾小時後又要求登入 | 先確認手機沒有清除網站資料；網站會自動更新一小時效期的存取憑證，暫時斷線不應清除已儲存的登入。真正被撤銷的憑證仍需重新輸入密碼。 |
| 首頁沒有最近上傳 | 該手機可能沒有此員工的本機上傳紀錄；不代表 Sheet 沒有紀錄。 |
| 戰報載入失敗 | 確認員工仍為登入狀態、Supabase RPC 權限與 `task_timing_records` 是否有同步資料。 |
| Sheet 紀錄沒有同步到 Supabase | 查看 X 欄錯誤內容、Apps Script「執行項目」與 `syncTaskTimingRecordsToSupabase` 觸發器。 |
| 網站沒出現程式更新 | 確認已執行 GitHub Pages deploy，並重新整理或清除瀏覽器快取。 |
