# 減少重複讀寫

首頁產品與員工清單沿用 localStorage 的 cache_products_v1 / cache_employees_v1，成功讀取後 10 分鐘內回首頁不再查詢。過期資料仍立即顯示，背景分別更新兩份清單；失敗不覆蓋舊資料或延長快取。空清單也可快取。個人設定的「重新載入資料」會略過期限強制更新；部分失敗會保留舊資料並提示重試。長時間停留首頁不會自行輪詢。

公告同步在 Script Properties 儲存上次成功內容的 SHA-256，依來源 Sheet 與 Supabase URL 區分。相同內容跳過整個 Supabase 請求；變更及清空仍寫入。只有 HTTP 成功後才記住摘要，因此失敗會在下次同步重試。同步鎖保留。synced_at 代表最後一次實際寫入，不再代表排程檢查時間。若手動在 Supabase 改動或刪除快照，要刪除對應 TASK_TIMING_NOTICE_DIGEST_ 屬性後重跑以修復。

前端需發布才生效；公告函式需更新到目前執行排程的 Apps Script 專案才生效，單純 GitHub Pages 發布不會更新 GAS。

驗證：113 項測試通過，涵蓋快取到期、空值、異常時間與公告不變跳過、失敗重試、刪除最後一則；前端 lint、正式建置通過。未修改線上程式或資料，尚未測量實際 Disk IO 節省幅度。

## 1.23.3 更新入口
個人設定的語言選擇之後、登出區上方提供「重新載入資料」，略過快取更新產品、員工清單及自己的年資資料。更新期間停用按鈕，成功或失敗後顯示結果。首頁與今日看板不放更新按鈕；看板維持進入時自動更新統計與公告，不會自動標記提醒已讀。
