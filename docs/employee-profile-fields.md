# 員工基本資料

主檔：瑞全資料中心 → 員工資料。

- D 性別：男／女／未填，可留空。
- E 國籍：台灣／越南／印尼／其他；下拉為建議，也可輸入其他國籍。
- F 到職日：真正的日期，顯示 yyyy-mm-dd；未知留空，不推測年資。

主檔為唯一維護來源。App 個人設定只讀取本人資料，不寫回主檔，也不依國籍強制切換語言。

## 儲存與同步

1. 套用 `supabase/migrations/20261023_employee_profiles.sql`。新增私有
   `task_timing_employee_profiles`，公開的 `task_timing_employees` 繼續只存登入名單。
2. 更新現有 Apps Script 專案的「員工同步.gs」，來源為
   `google-apps-script/task_timing_employees_sync.gs`。主程式與其他同步檔案不變。
3. 初次同步用 `syncTaskTimingEmployeeProfilesToSupabase`：只更新既有員工的三欄，
   不建立／刪除帳號、不修改密碼。
4. 日後原本的 `syncTaskTimingEmployeesToSupabase` 也會一起同步基本資料。
   任一基本資料批次失敗即回報失敗，禁止進入帳號刪除階段。

資料清空後同步會以 null 清除鏡像欄位；不替未填到職日配置年資等級。
日期物件以試算表時區轉成日期字串，避免台灣凌晨轉 UTC 時少一天。

舊 GAS `buildPayload` 也必須限制員工分頁只輸出編號、姓名（含依 index 選表），
且更新快取前綴；此保護需更新既有 Web App 部署才對外生效。

前端只在開啟個人設定時，以登入憑證讀取本人資料；不將性別、國籍、到職日
放入公開員工名單或 localStorage 快取。資料不可用時顯示重試，不影響報工。

## 年資徽章

本次僅建立基本欄位與讀取，尚未上線年資門檻或徽章。到職日補齊後，
再確認門檻、復職計算規則及顯示範圍。
